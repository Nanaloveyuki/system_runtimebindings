# HarmonyOS Logging and Build Integration

Status: accepted for the API 26 simulator slice. This decision records the adapter contract, upstream constraints and removal conditions for build compatibility code. Update it when those contracts or upstream versions change.

`ohos_runtimebinding` is a separate MoonBit module inside this repository. It depends on published BitLogger 0.11.1 and `shop1111/moonohos_ohos` 0.6.0, without AJNI. The Android module and its published package path remain unchanged. The Android publication excludes the HarmonyOS module directory.

For a HarmonyOS publication, copy the module's source, README, license and `.moonignore` to an isolated directory excluding `_build` and `.mooncakes`, then run `moon publish --dry-run` there. This was verified through server acceptance. Current packaging inherits the repository root's `.moonignore`; publishing the nested directory in place excludes its manifest. Root Android packaging was separately inspected and contains no HarmonyOS files. Neither new release was published in this slice.

`HilogSink` implements BitLogger's existing `sink_graph.Sink`; JSON formatting and record semantics remain BitLogger-owned. Trace maps to HiLog Debug because HiLog has no Trace level. The original JSON level, target, fields and timestamp are retained. Construction propagates MoonOHOS `HilogError`. Writes return Unit because the published HiLog interface discards `OH_LOG_Print` status. No fabricated fallible-write contract is introduced. Messages are public output and application callers control their content.

The device example uses BitLogger `core.Record` directly. Importing BitLogger's root `src` package brings in `moonbitlang/async/internal/c_buffer` and other host-native packages; MoonOHOS rejects their undescribed stubs before CMake generation. Do not bypass that check or add descriptor files for a host event loop. A portable logger surface belongs upstream in BitLogger; this adapter does not duplicate its filtering or logger implementation.

MoonOHOS owns export generation, Node-API registration, native dependencies, ELF verification and HAR preparation. The example is generated with `moonohos init` and replaces only the sample exports/page. The WSL build script invokes published MoonOHOS and DevEco OHPM/Hvigor, with the SDK's actual Windows compiler. It creates disposable path-translation tools and invokes Windows build tools from a Windows-mounted staging directory. It does not modify the installed SDK, CLI, package cache or global environment.

MoonOHOS 0.6.0's `compiler_commands` removes `-all-pkgs`. With MoonBit 0.10.19, replaying the resulting BitLogger formatting command fails E4037 for implicit core/ref and core/json. Adding the already-generated `_build/native/debug/check/all_pkgs.json` to that exact compiler invocation succeeds. The WSL command supplies this metadata through a scoped compiler bridge. Remove it once a published MoonOHOS version supports current MoonBit metadata. Its doctor also reads async metadata relative to the invocation directory; invoke from the clean disposable directory so unrelated project async versions are not mistaken for the CLI's compiled dependency. Build output and staging share a filesystem because upstream moves the final dist with rename.

Verified on 2026-11-03: HOS 7.0, API 26, x86_64; published CLI 0.6.0; native SDK 26.0.0.105. Strict export checks, actual SDK cross-compilation, HAR/HAP assembly, ELF verification and unsigned simulator installation passed. Two force-stop/start runs verified the ArkTS call and eight actual HiLog records. A screenshot showed the completion state and repeat button. ARM64 and physical-device signing remain unverified. Hvigor emits template version/local-module and missing-signing warnings; these are not suppressed or treated as successful signed release validation.
